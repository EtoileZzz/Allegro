# 作业统计改版（v0.5.2a）决策记录

这一轮把「作业统计」弹窗重做了一遍：从六个分页压到四个，热力图并进总览，
样式与动画整体对齐「任务数据分析」和「日程」，同时修掉两处看着别扭的地方
（热力图错位、逾期行列左侧的硬红竖条）。

每条都记「结论 + 理由」；待定项在最后。

---

## 一、结构

### D1 六个分页 → 四个：总览 / 趋势 / 按课程 / 记录
- **结论**：删掉「热力图」和「洞察」两个独立分页；热力图并进总览；洞察里
  最有用的三条（拖最久 / 按时率最好与最差 / 积压峰值）落在总览尾部。
- **理由**：360dp 上一行塞六个标签，字号已被压到 11.5px、内边距 6px，点击
  目标只有约 40×28；而任务数据分析只有四个分页 —— 页数不齐就谈不上"一致"。
  洞察页五条结论本来就是看完总览顺手扫的东西，不值得占一个分页。

### D2 「记录」仍然是第四页，没有拆成独立入口
- **结论**：记录页留在弹窗里，交互也不改：长按编辑 / 长按找回 / 行尾 ✕ 删除。
- **理由**：上一版刚把「作业记录」并进来（v0.5.2），再拆出去会让入口来回搬。
  真正难受的是"显示乱"，不是"入口错"，所以只整理排版与分组。

### D3 总览保持完整（KPI + 热力图 + 30 天柱 + 星期分布 + 三条结论）
- **结论**：接受总览变长，不删 30 天柱、也不删星期分布。
- **理由**：两者信息不重复（30 天柱看"最近节奏"，星期分布看"周几在勾"），
  删任何一个都是拿信息换高度；弹窗本来就能滚。

## 二、视觉与动画：只留一套

### D4 复用 `.tk-*`（任务数据分析那套），删掉 `.hwst-*` 约 110 行
- **结论**：作业统计的 KPI、分区标题、图表卡、洞察行、页签全部改用
  `tk-kpi / tk-kbar / tk-shead / tk-chart / tk-cbar / tk-axis / tk-wdrow /
  tk-ins / tk-muted / tk-statpage`；不再有并行的一套样式。
- **理由**：保留一套自己模仿另一套，下次改其中一边必定又漂移。共用类名是
  "一致"的唯一结构性保证，而且这次是删代码而不是写代码。

### D5 进场动画、图表动画与任务数据分析完全同源
- **结论**：开弹窗/切页 → `AR.Motion.pose(pageBox,'contentIn')`；柱子 → `tkGrow`
  460ms + 每根 +9ms 错峰；星期条 → `tkWipe`；折线 → `tkDraw`；热力图格子 →
  新增 `tkHeatIn`，按列 20ms 错峰。全部尊重 `prefers-reduced-motion` 与流畅模式。
- **理由**：v0.5.2 的作业统计是"翻页即硬跳"，而任务数据分析有完整进场 —— 这是
  用户明确点名的"动画也要一致"。

### D6 弹窗改回普通宽度
- **结论**：`openModal` 不再传 `wide: true`。
- **理由**：任务数据分析就是普通宽度；手机上两者宽度本来一样，但桌面上
  wide 会把内容拉稀，反而不一致。

### D7 KPI 改 2×2，带进度条
- **结论**：四格 KPI 从 4 列改 2 列，每格 21px 主数字 + 5px 进度条 + 一行说明；
  「未完成」那格用红色写「其中逾期 N 条」。
- **理由**：4 列时 10px 小字必然折行（"其中逾期 7 条"断成两行），主数字反而
  不如小字占地方。逾期信息按用户的选择统一收在这一格。

## 三、热力图

### D8 按真实周对齐（周一开头），不再按 84 天硬排
- **结论**：格子按"周一对周日"的列排；数据仍取 `taskStats().daily`（84 项，
  最后一项 = 今天）。
- **理由**：原来直接按索引铺 7 行一格，行标签「一…日」和真实星期对不上 ——
  今天是周一时，「今天」会掉到「日」那一行，最后一列其实是周二→周一，
  看起来就像把未来几天也画出来了。这是"不直观"的真正原因，不是多画了格子。

### D9 今天之后不画格子（留白），今天那格描主题色
- **结论**：未来日期的格子透明（不画），今天的格子 `inset 0 0 0 1.5px var(--accent)`。
- **理由**：留白能一眼看出"这周才刚开始"；虚线框那种画法会把视觉拉回"未来"，
  而用户明确选了留白。

### D10 去掉欠账红框，逾期信息收进 KPI
- **结论**：删掉 `.debt` 类、图例、详情里的欠账字样；总览「未完成」那格写
  「其中逾期 N 条」。
- **理由**：红框和"选中"框挤在同一个视觉通道（都是 inset box-shadow），高度
  11px 的格子上红框几乎比格子还显眼；逾期数字 KPI 里本来就有一份。

### D11 格子上保持 12px 小方格、靠左留白
- **结论**：不放大格子、不扩到 24 周。
- **理由**：格子放大到 24px 会变成"色块墙"，24 周则要动统计算法（84→168 天）
  并重做积压模拟；用户选了"12px 小方格靠左"，宽度只用一半是可接受的代价。

## 四、逾期行的左侧标记

### D12 2px 硬竖条 → 12px 向内投影（`inset 12px 0 14px -12px var(--danger)`）
- **结论**：`.hw-row.has-od` 改成左侧红色投影渐变。
- **理由**：硬竖条上下顶满，一条挨一条时像给整行镶了红边；投影只有 12px 宽、
  从红渐到透明，读起来是"这行有点问题"而不是"这行被框起来"。

### D13 设置里可改：四档 `solid / glow / both / bold`
- **结论**：设置 → 外观 →「作业逾期强调」的第二档从「左侧竖条」改为「左侧投影」，
  值从 `bar` 换成 `glow`；默认仍是「两者都要」（红底白字 + 投影）；老存档 `bar`
  在 migrate 里迁成 `glow`。
- **理由**：用户要求"这个设置在设置内也可以更改"。保留四档、只换第二档的实现，
  比新增第五档更不容易让老用户困惑（老值自动迁移，视觉上更接近）。

## 五、按课程页

### D14 点开就地展开条目，不再弹新窗
- **结论**：每门课一行（色点 · 课名 · 未完成数 · 完成率条 · 百分比），点行在行下方
  展开该课最多 8 条（未完成在前、截止近的在前），附「按时完成 x / y · 平均 n 天」
  和「在记录页看全部 N 条 →」（点了会切到记录页并把课程筛选设成这门课）。
- **理由**：原来的"点开只出一段文字明细，再点一次又弹一个新弹窗"是断层的根源；
  用户要的是"能动手的列表"。

### D15 删掉 `openCourseHomework`（那门课的独立弹窗）
- **结论**：函数与调用一并删除；它原来用的还是 `.hwst-*` 类。
- **理由**：改成页内展开后它没有调用方了，留着就是下次误用的坑。

## 六、记录页

### D16 逾期单独成段，排在今天/本周/更早之前
- **结论**：分组改成 逾期 / 今天 / 本周 / 更早；组内排序 = 未完成在前，
  再按截止日近的在前（没截止日的按布置日新的在前）。
- **理由**：用户原话是"没有轻重缓急，看着都一样重"。逾期单独成段 + 行内红色
  截止日 + 左侧投影，轻重自然拉开，不用再加"拖了 N 天"这种噪音。

### D17 更早按周分组，最近 4 周展开 2 周，其余收进「更早的 N 周」
- **结论**：更早段按周一为一周分组（`10/19–10/25 · 6 项`），默认展开最近 2 周；
  第 5 周及更早全部收进一个「更早的 N 周 · M 项」折叠层。
- **理由**：12 周若全列出来就是 11 个空组头，一屏全是标题，比原来那条长列表
  还难扫。

### D18 筛选从两排 chips 收成两种单行
- **结论**：状态用 chips（全部 / 未完成 / 已完成 / 本周），课程用**单行横向滚动**
  chips（不再换行）。
- **理由**：原来两排都是可换行的 chips（4 + 5 个），课程那排必然折成两行、吃掉
  约 66px；改成不换行滚动后每排只占一行。

## 七、工程约定

### D19 统计口径、同步、存储一个字节都没动
- **结论**：仍然只消费 `taskStats()`；没有新增字段、没有新的同步键、
  没有新的 localStorage 项。`verify-homework` 的 H1–H52 口径断言原样通过。
- **理由**：这轮是纯表现层重构；动口径会让上一版的修复（按时率分母、欠账
  模拟）重新暴露风险。

### D20 版本号 0.5.2a / versionCode 76
- **结论**：75 已发布，必须往上；本轮是表现层修订，用尾字母版 0.5.2a。
- **理由**：`versionCode` 不涨就会被系统拒绝安装；尾字母是项目既有习惯
  （0.5.1a/b/c 先例）。

## 待定 / 下轮可再看

1. 热力图 12px 靠左后右侧留白较多 —— 要不要在图例旁放一句"最近 12 周共 N 条"？
2. 「在记录页看全部」目前只带课程筛选、不带"只看未完成"，是否要一起带上？
3. 记录页课程 chips 横向滚动没有右侧渐隐提示，短屏上可能看不出还能滑。
4. 逾期投影在人眼里仍偏红（深色主题下尤其），若还嫌重，可把
   `inset 12px 0 14px -12px` 调成 `inset 10px 0 12px -12px`。

### D21 顺手修掉「内容进场」的空转（`pose()` 不是动画函数）
- **结论**：新增 `playContentIn(node, name)`，用 `AR.Motion.get()` 取「卡片内容浮入」
  的时长/曲线/位移，再用 WAAPI 播一次；作业统计的 `hwStatPaint` 与任务数据分析的
  `paintPage` 都改用它，另外两处「最近记录展开」的同类调用也一并换掉。
- **理由**：核查时发现 `AR.Motion.pose(node, 'contentIn')` 全程是空转 ——
  motion.js 里的 `pose(p)` 只接一个参数，它是「姿势 → 关键帧」的转换函数；
  带第二个参数调用时只是把 DOM 节点当姿势对象算了一遍关键帧并丢掉。
  也就是说这两处统计弹窗以前都没有真正的进场动画，只是看起来"写了"。

## 八、第一轮验收后的 8 条（v0.5.2a 收尾）

### D22 「按课程」的进度条改名 `.tk-crow-bar`（撞名 bug）
- **结论**：课程行进度条不再叫 `.tk-cbar`，改成 `.tk-crow-bar`。
- **理由**：`.tk-cbar` 是「任务数据分析」的柱子类名，后定义的课程行规则把它覆盖成
  64×6px 灰圆角块，导致「近 30 天」整张柱状图不可见（只剩背景光斑）。

### D23 流畅模式 / 减弱动画下折线要「画到底」
- **结论**：`body[data-perf]` 与 `prefers-reduced-motion` 分支里，除了
  `animation:none`，再补 `stroke-dasharray:none; stroke-dashoffset:0`。
- **理由**：折线靠动画把 dashoffset 从 1400 拨到 0；只关动画就会让它永远停在不
  可见状态。任务数据分析那边同样受益（同一个选择器）。

### D24 三条结论从总览搬到趋势页
- **结论**：总览只留 KPI + 热力图 + 30 天柱 + 星期分布；三条结论（拖最久 / 按时率
  最好最差 / 积压峰值）放在趋势页折线下方。
- **理由**：用户验收时要求「把洞察相关文案移动到趋势下」——总览本身已经很长，
  趋势页看完折线顺手看结论，语义也更顺。

### D25 任务贡献图与作业热力图统一规则
- **结论**：未来的日子不画格子（透明），今天那格描一圈主题色。
- **理由**：贡献图原本已经把本周未来几天画成「0 次」灰格，与作业热力图「今天之后
  留白」的规则不一致，看起来就像没按真实周对齐。

### D26 热力图两档大小（设置 → 外观）
- **结论**：新增 `appearance.heatSize`：`sm`（12px 方格靠左，默认）/ `lg`（12 周
  铺满宽度、格子 24px）。切换即时生效（`body[data-heat="lg"]`）。
- **理由**：小格子省地方但点起来费劲；大格子铺满宽度更好点，也不动统计窗口
  （84 天不变，不碰积压模拟）。

### D27 热力图点开那天可以「展开 →」去记录页
- **结论**：热力图详情行末尾加「展开 →」，点了切到记录页并带一个「8/24 那天 ✕」
  筛选 chip（按布置日或完成日匹配），可点 ✕ 取消。
- **理由**：看热力图的人下一步基本就是「那天到底做了啥」；与其在弹窗里再叠一层
  列表，不如直接到记录页（那里本来就能长按改、✕ 删）。

### D28 记录页课程 chips 露出滚动条
- **结论**：`.tk-chips` 从 `scrollbar-width:none` 改成 `thin`，并给 WebKit 加
  6px 滑块。
- **理由**：桌面端没有横向手势，滚动条藏掉等于最后几门课点不到（实测 312 宽容器
  里有 340px 内容）。

### D29 展开 / 折叠 / 切页改成补间，不再整块硬跳
- **结论**：`tkSlide(node, open)` 做高度补间（展开 200ms、收起 160ms，带透明度），
  `tkFadeRows` 做行错峰浮入（14ms 间隔）；切页先淡出 90ms 再换内容；
  「按课程」展开只就地插/删那一段，不再整页重画。
- **理由**：用户反馈「按课程 / 记录那里的动画还有各种展开动画太生硬」。原来所有
  交互都走 `innerHTML` 重画，高度直接跳、旧的滚动位置也没了。
- **注意**：淡出动画必须 `fill:'both'` 后在 `onfinish` 里 `cancel()`，否则容器会被
  钉在 `opacity:0`（第一版就踩了这个坑，切页之后整页空白）。

## 待定 / 下轮可再看

1. 大号热力图（lg）在 320dp 上格子会被压到 ~17px，是否需要第三档「中」。
2. 记录页「那天 ✕」筛选目前按「布置日或完成日」匹配，如果想只看"那天完成的"，
   要再加一个切换。
3. `tkFadeRows` 的 14ms 间隔在记录页 30+ 行时总时长被 `Math.min(i*14, 260)` 截断，
   行数很多时后面几行是同时亮的，是否改成更短的间隔。


## 九、第二轮验收（同一次打包）

### D30 「按课程」展开状态不跨页保留、且只允许一个展开块
- **结论**：换页时 `HW_STAT.courseOpen = null`；展开前删除所有其它 `.tk-cbody`。
- **理由**：用户在记录页筛完课再进按课程，点同一门课会被判成「收起」→ 看起来像"点不了"；
  换课程时旧块不删会叠出两份（实测一次点击后出现 2 个 body / 16 行）。

### D31 展开课程时清掉跨页筛选
- **结论**：展开某门课时 `HW_STAT.day = ''`、`HW_STAT.course = 'all'`。
- **理由**：热力图那天筛选 + 记录页课程筛选 + 按课程展开，三种状态叠加后用户无法判断
  列表是被谁筛的。展开课程 = 明确的单门课视图，先把别的筛选清掉。

### D32 高度补间只动 height
- **结论**：`tkSlide` 的关键帧去掉 opacity。
- **理由**：展开时 `tkFadeRows` / `playContentIn` 已经在改透明度，两层叠加会闪一下。

### D33 洞察文案按「趋势」重写
- **结论**：三条结论改为：近 7 天 vs 上期（多/少几条、7 天里有几天动过）/ 当前连续与最长连续 /
  最长空窗 + 积压峰值。
- **理由**：原来那三条讲的是课程好坏与积压，挂在趋势页说不通；趋势页应只讲走势与节奏，
  课程维度归「按课程」页。

### D34 任务贡献图的未来留白规则要排在主题/流畅模式配色之后
- **结论**：`.tk-gh-cell.future` 的透明背景写在 `body[data-perf][data-theme="dark"] …` 之后，
  并显式覆盖 `body`、`[data-theme="dark"]`、`[data-perf]` 三档。
- **理由**：第一版写在前面，被同优先级、但位置更靠后的配色规则盖掉，未来格子看起来还是实心灰。

### D35 大号热力图同步到任务贡献图
- **结论**：`body[data-heat="lg"]` 下 `.tk-gh-cell` 22px、`.tk-gh-col` 等分宽度、星期列 22px。
- **理由**：同一份设置应该管两个热力图，不然「大/小」只对作业统计生效，看着像没生效。


### D36 课程展开的开关状态改由 DOM 决定
- **结论**：点课程行时先看它后面有没有 `.tk-cbody`：有就收起，没有就展开；
  `HW_STAT.courseOpen` 只用于"重画后要不要自动展开那一门"。
- **理由**：状态存在变量里、DOM 是另一份真相，两者一旦错位，点击就会变成"收起一个不存在的东西"
  —— 表现就是彻底点不动。顺带给每个节点加 `__hwB` 标记，避免 paint 两次把 click 处理器叠起来。

### D37 记录页段内按课程分组
- **结论**：逾期 / 今天 / 本周 / 更早的每周内部，再按课程分组（色点 + 课程名 + 条数），
  只有一个课程时不显示组头；组内仍按截止日排序。
- **理由**：用户要求"记录那里的条目也按课程分组"；时间分组回答"什么时候"，课程分组回答"哪门课"，
  两级叠加后一眼能定位，也不用再靠课程筛选 chip 来回切。
