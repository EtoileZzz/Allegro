# 决策记录：作业模块升级（0.5.2）

> 主题：把「我的」页的作业卡 / 作业条目做得像「任务」「日程」那样。
> 记录规则：每条只写「结论 + 理由」。未定的放最后。

## 已定

### 1. 拷打强度与记录方式
- **结论**：强度 4（深挖），保留本决策记录。
- **理由**：这次要动数据模型（截止日）+ 同步配对 + 三处 UI，回归面大，留在纸上比留在脑子里稳。

### 2. 三类条目的边界
- **结论**：作业 = 一次性、挂在「某天」上（可带一门课），没有节奏、没有累计目标；任务 = 有节奏或累计目标；待办速记 = 临时、不追踪。手动添加的作业不提供「每天/每周」。
- **理由**：作业已经有「布置日 + 课程」两个天然坐标，再叠节奏就变成第二套任务系统，用户会不知道该往哪加。

### 3. 文字的真源（备注 vs 条目）
- **结论**：双向同步 —— 编辑作业文字时，若还能**唯一定位**到备注里那一行，就把备注那行一起改掉；定位不到（备注里有两行一样、或备注已被改）就自动**脱钩**（`detached:true`），此后不再跟备注配对。
- **理由**：不用逼用户理解「备注和条目谁说了算」；`(blockId, 布置日, 文字)` 是现有配对钥匙，猜错行会把别的作业改掉，所以只在能唯一定位时才回写。

### 4. 截止日
- **结论**：加 `tasks[].due`（本地日期键 `YYYY-MM-DD`，可空 = 无截止日），**不动提醒链路**（`reminders.js` 一行不改，截止日不产生任何新通知）。
- **理由**：用户明确选「加截止日但不动提醒」。提醒刚修完一轮回归，再动风险大于收益。

### 5. 未完成作业的排序
- **结论**：**保持不变**（按布置日升序），截止日只做标记，不参与排序。
- **理由**：用户选的「只加标记」。排序一改，用户已经形成的「最上面是最老的账」的手感会乱。

### 6. 作业统计卡
- **结论**：保留并升级为真统计（完成率 + 按课程可点进去 + 近 30 天趋势）；作业卡头部加汇总条、卡底加「作业记录…」「＋ 添加作业」。
- **理由**：用户选「两张都留」。任务卡是「当下该做什么」、数据分析弹窗是「趋势」，同一个分工照搬到作业上，两处共用一套列表/弹窗代码。

### 7. 跨天回溯
- **结论**：不做时间线分组、不做日历视角、不做搜索。历史全部走「作业记录…」弹窗（现有三组：未完成 / 今天完成 / 更早的已完成），只把它挪到显眼入口并支持编辑。
- **理由**：用户选「不需要，弹窗里能看到就行」。日历模块已经能看当天；再加一套分组视图是纯维护成本。

### 8. 编辑入口
- **结论**：**长按未完成行出菜单**（具体菜单项待定，见下）。滑动仍然是划掉，长按是「改」，两个手势分工。
- **理由**：用户选的「长按出菜单」。点行目前是空手势，但用户没选它，按用户的来。

### 9. 发布
- **结论**：一批做完直接出 **0.5.2（versionCode 74）**，APK + EXE + src 三件套，签名不变（`CN=EtoileZzz` / 证书指纹 `2f38aa94…8721`），提交 release 前先把三件套和说明交给用户检查。
- **理由**：数据模型一次改完、回归一次跑完，比分两批两次回归便宜；用户要求「告诉我截止日准备怎么做」并认可一批出。

## 数据模型的连带风险（记录，不需要用户决定）

1. **备注来的条目被删后会复活**：`findTask` 跳过 `deletedAt`，`rebuildTasks` 会把删掉的行再建出来。→ 改为命中已删条目时视为「用户删过这行」，不重建。
2. **改文字会让旧条目复活**：配对钥匙含文字。→ 与第 3 条一起解：能唯一定位就回写备注；不能就脱钩。
3. **手动加的作业会飘在所有学期**：`semesterOfTask` 取不到 `semesterId`/`courseId` 就当「不分学期」。→ 手动添加必须写当前 `semesterId`。
4. **跨设备同步按 `(课程/时段 + 布置日 + 文字)` 配对**：改文字后另一台设备会看成两条。→ 靠 `detached` + 备注回写降低概率；发布说明里写「升级前先把所有设备升到 0.5.2」。
5. **老版本设备会抹掉 `due`**：记录级 LWW 取整条更新的一侧。→ 同上一条：先升级所有设备。

### 10. 截止日的默认值
- **结论**：手动添加时默认**留空**；选了课程才出现一键「下次这节课 · 3/14」，点一下才填。
- **理由**：作业大多是「下次课上交」，但这个推断不该默默替用户做——填错了比不填更烦。一键填需要新 API `nextLessonOfCourse(courseId, fromDate)`，要处理周次、单双周、调课、停课。

### 11. 长按菜单的项
- **结论**：未完成行长按 → 三项菜单：**编辑… / 设截止日… / 删除**。已完成行长按仍是「找回」，不变。
- **理由**：设截止日是最常用的快捷操作，单独一项比「先开编辑再找日期」少一步；「改课程」会让条目脱钩，收进编辑弹窗里更合适。

### 12. 逾期的视觉
- **结论**：**标签变色 + 行左侧 3px 竖条**。标签用 `rgba(229,72,77,.12)` 底 + `var(--danger)` 字（和任务卡「逾期」标签同一套），行加 `border-left: 3px solid var(--danger)`。
- **理由**：项目里 `.issue` 已经在用「左侧竖条警示」这套语言；整圈 1px 描边会让列表每条都带个圈、显得碎；文字整行变色会盖过课程色点。

### 13. 完成率口径
- **结论**：完成率 = **该期间布置的**条目里已完成的比例（本周：本周布置的；本赛季：本学期的）。近 30 天趋势按**完成日期**数条数，一天一根细条。截止日不参与任何统计（不做「按时完成率」）。
- **理由**：「本周布置的做完了多少」才是作业的进度；按完成时间算会把上周遗留的进度算进本周。

### 14. 备注存储位置（已核实）
- **结论**：备注存在**单次记录** `overrides[].newNote` 上，钥匙是 `(blockId, 日期)`，写入走 `upsertOverride`；`block.note` 只是老数据兜底。
- **理由（连带实现约束）**：`syncTasksFor` 会把「备注里不存在的文字」软删除，所以改文字必须**先改条目、再改备注行、最后同步**；并且改之前要预判「新文字在这段备注里唯一、旧文字也唯一」，否则直接脱钩——先改备注再同步会把旧条目当成删掉的行。

### 15. 删除「备注里来的」作业
- **结论**：**只删条目，不动备注**。删过的条目会被记住（`findTask` 命中墓碑后不再重建），备注里那一行留着也不会再自动长回来。
- **理由**：备注是用户当时写的课堂笔记，顺手改笔记的风险大于收益；对称性由「记住删过」这一条兜住。

### 16. 手动作业的归组
- **结论**：没有课程的手动作业归**「未分类」**（和「课程已删」的条目同一个筐）。
- **理由**：分组头已经有一个「未分类」，不再新增概念。

### 17. 备注来源作业的默认截止日
- **结论**：备注识别产生的**新**条目，自动写 `due = 这门课的下一次上课日 − N 天`。N 默认 1（前一天），设置里可选 上课当天(0) / 前一天(1) / 前两天(2) / 不自动设。「下一次上课」从布置日 **+1 天**起往后最多 28 天，用 `dayItems()` 逐天找（周次 / 单双周 / 调课 / 停课自动算对）；算不出来（未分类、课表里没这门课、28 天内没有）→ 留空；算出来早于布置日 → 钳到布置日。
- **理由**：用户指定「默认下一次上课日前一天，设置里可以更改」。作业基本都是下次课交，这个默认值命中最广；算不出来必须能留空，否则未分类条目会拿到假日期。手动添加仍走「留空 + 一键」，不自动填。

### 18. 默认截止日存字段，不现算
- **结论**：**存进 `due`**，只影响新建条目；老条目、手改过的、以及之后重建备注都不重算。
- **理由**：没有连带提醒，它只是一个显示标签；存下来可预测、可手改。调课之后不跟着变是可接受代价（想跟就在编辑里改）。

### 19. 「仅数据」同步范围的两个 bug（用户报「设为仅数据后，每次改设置仍会同步」）
- **结论**：① `onLocalSave()` 加指纹判断——范围=仅数据且 `dataSig` 没变时**不排同步**（不标待同步、不发请求、不弹 toast）；② 推送时把**云端已有的 settings 原样放回去**（没有就写 `{}`），本机设置永不外传，也不会再抹掉云端那份；③ `restoreRev()` 也遵守范围（`mergeSettings: scope !== 'data'`）。
- **理由**：范围以前只决定「传什么」，从没决定「要不要传」，所以每改一个设置都会 GET+PUT、rev+1、弹 toast。而 `delete payload.settings` 会让云端那份设置永久消失——重装设备就再也拿不回来。

### 20. 同步修复的发版
- **结论**：并入 **0.5.2（versionCode 74）** 一起发。
- **理由**：两批改动都还没发布，分两次发只会多出 tag 和三份资产。

### 21. 背景三档（追加需求：可以关闭背景的渐变色块）
- **结论**：外观 → **背景** 三选一：**色块（默认）/ 纯色 / 渐变（主题色）**。后两档同时把三个 `.blob` 隐藏；纯色 = `--bg-base`，渐变 = 用 `--accent-glow` / `--accent-soft` 做的极淡径向底色。默认仍是色块，老用户视觉不变。
- **理由**：用户先要「可以关闭背景的渐变色块」，又补充「可选纯色或者对应主题色渐变」——所以做成三选一，而不是一个开关；比开关少一次「关掉后要什么」的追问。

### 22. 0.5.2 的内容边界
- **结论**：0.5.2 同时包含 **作业模块升级 + 「仅数据」同步修复 + 背景三档**。
- **理由**：三块都已经做完、一次回归一次发布；用户明确要求「一批出 0.5.2」。

## 第二批（0.5.2 重打，versionCode 75）：作业行样式 + 「作业统计」弹窗

### 23. 划掉作业会卡住（用户报）
- **结论**：滑动与长按合并成**一套指针逻辑**（`bindSwipeRow` 里加 `onHold`：手指移动超过阈值就取消长按；长按只在没移动时触发）。不再给同一行挂两套各自 `setPointerCapture` 的监听。
- **理由**：两套监听互相抢指针捕获，松手时滑动那套收不到 `pointerup`，行会停在半空。任务那边已经有 `tkBindLongPress`（只监听、不抢捕获）的先例，说明"一套手势管理"才是对的做法。

### 24. 作业行样式
- **结论**：左边 **布置日**（原样，主题色 chip），右边 **截止日**（同一种 chip，改成红色）。**删除「挂账」字样与「挂 N 天」标签**；逾期只用红色（和红框）表达。
- **理由**：用户原话「左边和原来一样显示添加日期，右边用红色相同样式显示截止日期」「把挂账这个表述删除」。

### 25. 「作业记录」按钮改名「作业统计」，并吃掉记录
- **结论**：一个弹窗 **六页**：总览 / 趋势 / 热力图 / 按课程 / 记录 / 洞察。所有入口（作业卡卡底、设置 → 作业与日程）都开它；「记录」是其中一页，保留编辑 / 删除 / 长按找回 / 清理 30 天前的已完成。
- **理由**：用户选「五页一个弹窗」，又在第二轮追加「第六页洞察」。

### 26. 热力图的度量与色阶
- **结论**：格子 = **当天完成几条（按完成日期）**；色阶**固定** 1 / 2 / 3+ 条；另用红框标「那天布置了但到今天还没勾完」。跨度固定 **12 周**。
- **理由**：用户选了「完成日 + 完成条数」，并同意固定档位（作业一天通常 0–3 条，分位法会把 1 条标成满色），跨度选 12 周与任务热力图同尺度。

### 27. 按时完成率
- **结论**：只统计**有截止日**的条目；分母 = 有截止日且（已完成 或 已过截止日），分子 = 在截止日当天或之前完成。未到期且未完成的不进分母。卡片上注明「仅 N 条有截止日」。
- **理由**：还没到期不能算迟到；而一旦过期就自动进分母，不需要额外标记，每次现算。

### 28. 「我的」页的作业统计模块卡
- **结论**：**删掉**这个模块；统计统一从作业卡卡底进。旧配置里的 `hwstats` 在 `migrateCustomModules` 里丢弃（不再渲染）。
- **理由**：用户选「删掉这个模块」。两套统计代码一定会跑偏（本版刚吃过一次两处各算一遍的亏）。

### 29. 记录页的筛选
- **结论**：两排 chips —— 状态（全部/未完成/已完成/本周）+ 课程（全部课程 + 有用到的课程 + 未分类），两排可叠加；课程 chips 只在用到的课程 ≥ 2 时才出现。
- **理由**：用户选「状态 + 课程两排」。「高数那几条还在不在」是作业记录里最常见的问法。

### 30. 洞察页的五条
- **结论**：① 哪门课拖得最久（未完成平均已挂天数 + 已完成平均布置→勾掉天数）② 按时率最高 / 最低的课 ③ 平均多久勾掉一条 ④ 最忙的一天 / 积压峰值 ⑤ 连续天数 / 最长空窗。
- **理由**：用户把五条全选了。都是现算，不额外存字段、不进同步。

### 31. 六分页的窄屏排布
- **结论**：**收窄内边距**，标签保留全称（总览 / 趋势 / 热力图 / 按课程 / 记录 / 洞察）。分段控件改为 `gap:3px; padding:3px`，`.seg` 改 `font-size:12px; padding:6px 7px`；≤400dp 再降到 `11.5px / 6px 6px`。
- **实测**：360dp 直板机的弹窗内容宽 = `min(660, 100vw-32) - 36` = **292px**；收窄后六标签合计 **≈275px** → **一行放得下**。320dp（可用 252px）自动折成 3+3，胶囊按矩形落位能跨行跟过去。
- **理由**：用户选「收窄内边距」。不改文案、不引入下拉，窄屏只付一次字号代价。

### 32. 逾期与未到期的区分（用户定稿）
- **结论**：截止日 chip **一律红色**；逾期的强调方式**默认「红底白字 + 行左侧竖条」两样都要**，并且在 **设置 → 外观 → 作业逾期强调** 里可改：红底白字 / 左侧竖条 / 两者都要（默认）/ 加粗。
- **理由**：用户明确要「2 和 3」（红底白字、左侧竖条）并且要求「设置-外观里可改」。做成 `settings.appearance.overdueStyle` + `body[data-od]`，和背景那套一样：一条属性、几条 CSS，不在 JS 里逐个改样式。

### 33. 版本号
- **结论**：这批**不升 0.5.3，重打 0.5.2**，但 `versionCode` 从 74 提到 **75**（versionName 仍 0.5.2）。
- **理由**：用户要求「版本 0.5.2」。名字不变、代码号必须往上，否则已装 74 的设备覆盖升级会被系统拒绝。
